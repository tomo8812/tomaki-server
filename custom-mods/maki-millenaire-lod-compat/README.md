# Maki Millénaire Chunksmith Compatibility 1.0.10

Minecraft 1.21.1 / Chunksmith 4.8.1 / Millénaire 9.1.0の事前生成互換MODです。

Chunksmithの事前生成中に候補を保留し、プレイヤーがその領域をロードしたときにMillénaireのキューへ戻します。建築前に、必要な領域のFULLがロード済みで、[Chunk Cache](../maki-chunksmith-chunk-cache/README.md)から通常保存へ引渡し済みであることを読み取ります。

## 候補数とキューの閾値

現在の[Controller設定](../../config/maki-chunksmith-controller.properties)は半径4096ブロックの円です。半径256チャンクの整数格子には205,861座標があり、約20.6万チャンクになります。村間隔が500ブロックでも、生成位置を選ぶ前の候補は最大で各チャンク1件です。候補数の見積もりには建築済みの村の数を使いません。

| 対象 | 規模・扱い |
| --- | --- |
| 1つの事前生成範囲 | 最大約20.6万候補。生息可能バイオームの判定で実数は減少 |
| 世界全体の保留記録 | 未探索領域の分をSavedDataに保持。nativeキューの上限で切り捨てない |
| native通常候補＋SiteHunterへの投入 | 合算262,144件を受付上限にする。現在の1範囲全体が収まる次の2の累乗 |
| native孤立建築再試行への投入 | 独立して262,144件を受付上限にする。通常候補の投入を止めない |
| 再投入 | 20tickごとに各キュー最大64件。native SiteHunterの1tick分の最大調査数に相当 |

移動先での事前生成が累積すれば、保留記録は数百万・数千万件になります。通常候補は座標を64bit整数で保持し、100万件の座標配列は約7.6MiB、1000万件は約76.3MiBです。HashSet・NBT保存中の配列・孤立建築の追加情報・Millénaire自身の候補オブジェクトは別にメモリを使用します。100万件の保留と再読込を自動テストします。実ワールドの累計生成数や1000万件での実サーバー性能は未計測です。

再投入時はプレイヤーの読込範囲の座標から保留記録を直接照合します。世界全体の数百万件を毎tick走査しません。nativeキューが上限に達しても、対象の保留記録を残して空きができた時に再投入します。村・孤立建築の生成判断、建築、TTL、再試行はMillénaireが処理します。

## 保存と1.0.10への更新

各ディメンションのSavedData `maki_millenaire_lod_pending` に、通常候補を `mainCandidates`、孤立建築再試行を `loneRetries` として分けた形式3で保存します。通常候補はまだ村・孤立建築の生成先を決めていないnative通常キューの候補です。孤立建築再試行には位置・距離・待機開始時刻・再試行時刻を保存します。

起動時に全ディメンションの保存データを読み込み、旧形式1/2の座標だけの `pending` を削除します。形式2には形式1から種類不明の記録を引き継いだ可能性があり、通常候補だと証明できないためです。形式2で孤立建築と明示され、必要な情報が揃う記録は引き継ぎます。不完全な孤立建築記録も削除します。整理件数をログに出し、次のワールド保存で新形式を確定します。既に建築された村や建物は変更しません。

通常のワールド保存・サーバー停止を経て再起動した後も、新形式の保留候補を再投入します。実行中キューへの投入済み印は再起動時に解除します。チャンク読込側の経路も孤立建築再試行を通常候補へ変換しません。SiteHunterへ渡った候補はMillénaire自身がチャンクに保存する候補状態から復元します。強制終了時は最後に保存された状態までの引継ぎです。

ChunksmithがLODを管理し、Chunk Cacheが実チャンクの保存・復元・引渡しを担当します。このMODの処理範囲は、候補の保持・再投入と建築準備の確認です。

## 検証

プロジェクト内で `gradle check jar` を実行します。上流API・Mixin注釈、現在の生成範囲に対するキュー閾値、通常候補と孤立建築の独立した投入、100万件の保留、旧形式の整理、NBTファイルへの保存・再読込、孤立建築再試行の復元を検証します。
