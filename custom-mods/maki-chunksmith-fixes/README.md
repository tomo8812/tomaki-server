# Maki Chunksmith Fixes 1.0.0

Minecraft 1.21.1 / NeoForge 21.1.262 / Chunksmith 4.8.1専用のサーバー修正MODです。LOD保存処理の修正と、変更された実チャンクからの既存LOD更新を担当します。

- LODの存在マークをCSLODストアへの書込成功後に付けます。新規LODの保存失敗・未投入は独自に記録せず、再起動後などのChunksmith本来の未生成走査に任せます。
- 既存LODのあるチャンクについて、ブロック状態が実際に変わった回数を数えます。既定32回で更新対象になり、最後の変更から60秒間変更が止まった後、`lodFromExploredChunks=true`かつLOD有効時に更新タスクを作成します。[設定](../../config/maki-chunksmith-fixes.properties)で回数と待ち時間を変更できます。同じ位置の繰り返し変更も数えます。投入待ち中やチャンク読込中に変更が再開した場合も、待ち時間を取り直します。
- 更新タスクはControllerへ渡し、リソースに応じた投入を受けます。プレイヤー参加中も更新できます。既存FULLを読み込んでLODを抽出し、実チャンクを再生成しません。
- 更新対象はストア内の`maki-lod-refresh.pending`へ非同期記録します。該当スナップショットの保存完了後に解消し、失敗時は対象を残して再試行します。保存中に加わった変更は未反映分として残します。閾値未満の回数はメモリ内だけで管理します。
- 初回LODの書込待ち中の変更もメモリ内で数えます。初回保存が成功した後、未反映の変更が閾値に達していれば更新対象にします。初回保存に失敗した場合は本体の未生成走査に任せます。
- 更新対象の記録は補助情報で、Minecraftの通常保存を止めません。既存LODは通常保存・アンロードだけでは再抽出しません。LODのないチャンクは本体の取得経路を利用します。
- ネイティブキュー満杯時の同期書込が先行しても、古いレコードが新しいLODを上書きしないようにします。古いレコードの破棄は実書込成功と区別し、本体の保存件数・保存量にも加算しません。
- 失敗した`ChunkResult`をChunksmithのFutureにも失敗として伝えます。本体のチケット解放・settle登録処理は維持します。

Controllerは投入量と完了の監視を担当し、本MODは更新対象と保存結果を管理します。村生成や村の活動、Dioramaへの表示範囲は扱いません。

`gradle check jar`で、実CSLODストアの保存・失敗・更新順序、更新閾値と待ち時間、保存中の変更、新規LOD失敗で更新対象を作らないこと、チャンク取得失敗の通知を検証します。
