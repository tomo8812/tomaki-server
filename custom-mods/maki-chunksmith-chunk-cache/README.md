# Maki Chunksmith Chunk Cache 1.5.0

Minecraft 1.21.1 / NeoForge 21.1 / Chunksmith 4.8.1用の一時実チャンクキャッシュです。

Chunksmithが生成した一時FULLチャンクを、Entityスナップショットとともに通常のregion保存先から退避します。プレイヤーがロードすると、通常FULLを優先し、必要な場合にキャッシュを復元して通常保存へ引き渡します。引渡し後の変更は通常ワールドへ保存されます。Cacheはチャンク・Entity・POIの保存完了を確認して、退避データを削除します。

通常保存先にFULLがある座標と、通常保存可能なFULLが既にメモリ上へロードされている座標では、新しいキャッシュ保存を開始しません。通常FULLと併存する未使用キャッシュは、通常チャンクIOの書込完了を待って削除します。既にロード済みの座標も10秒間隔の整理対象に含め、再ロードや新たな保存がなくても、通常保存先のFULLを確認できれば重複を削除します。通常保存が未完了の座標と引渡し中の座標は保持します。引渡し中の退避データは、チャンク・Entity・必要なPOIの保存ACKを待つ経路で整理します。

LODの生成・保存・再利用・互換性判断はChunksmithが担当します。このmodはLODファイルを走査・検証・更新せず、LOD不足を補うためのチャンク生成も行いません。

## Controllerとの連携

FULL検証とFULL書込の実開始・実終了、保存確定・既存FULL再利用・失敗を、Controllerが発行した同一試行tokenで通知します。論理タイムアウト後も、開始済み処理の完了通知は実際の終了まで待ちます。生成投入・WIP窓・並列数探索・FULLとLODのPAIR計測はControllerが担当します。

FULL保存が3回続けて失敗した場合は、Chunksmithの要求待ちを終了し、同じ実チャンクの保存を1200tick間隔で再試行します。実チャンク・通常保存の保護・native ticketは、保存成功またはプレイヤーへの引渡しまで保持します。要求待ちの終了を保存成功として通知せず、Controllerには未完了として記録します。

## 保存形式と既存データ

固定保存先ID `f00dcace0000000000000003` とschema 3を維持します。新しい保存完了印は `fullCommitted` です。有効なFULLはLODの保存成否によらず復元・再利用できます。FULLとLODが両方完成したかの計測はControllerが行います。旧schema 3の `lodCommitted` は過去のFULL公開完了印として読み取ります。LODファイルの存在や内容を参照せず、旧FULLは新しい印の欠如だけで無効化しません。

旧世代のFULLは採用IDを原子的に記録した後、検証済みファイルを一件ずつ同じファイルシステム内で原子的に移動します。移行用の二重容量を必要とせず、中断後も残りから続行できます。隔離領域からの復旧は容量を確保してコピーし、所有権が不明なファイルと競合する有効データは保持します。採用先の検証と受入マニフェストの保存後、バイト単位で一致する移行元を削除し、空になった旧ディレクトリも削除します。異なる有効データや検証できない残存物は隔離領域で保持期限に従って整理します。移動・復旧ともにプレイヤーへの引渡しclaimを確認し、引渡し前のFULLを再公開しません。NBT形式、座標、ディメンション、FULL状態、Entityと地形セクションを検証します。

容量不足で保留した隔離FULLの復旧は、現行cacheの利用可能状態とは別に、稼働中のmaintenanceから最短60秒間隔で再試行します。保留中の元ディレクトリは期限・世代数・容量による自動整理から外し、復旧完了後に通常の整理規則へ戻します。復旧コピーも通常の公開時と同じ所有権ガードを通し、プレイヤーへ引渡し中の座標には再公開しません。

## 検証

プロジェクト内で `gradle check jar` を実行します。FULL形式・旧世代移行・中断された引渡し・保存ACK・容量制限・タイムアウト競合を検証します。
